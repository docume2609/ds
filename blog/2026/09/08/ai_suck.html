我々の世代がプログラムを書ける実質的な最後の世代になる

2026年9月8日 · 約63分

（全体俯瞰 : AI 生成） click で拡大

前置き​

予想はしていたが、ごく最近になって

  • なんてこった！ プログラム・コード作成の喜びを AI に奪われてしまった！

…といった告白をするソフト開発者を立て続けに何人も見かけるようになったので、その一例の動画を取り上る。

コメント​

数か月前、AI と対話しながら特定用途向けのソフトウエア・ツールの作成を仕様策定レベルから実稼働、機能追加まで一気に行ったが、実にあっけないものだった。その時、私は雑談として以下のように AI に語った。赤字部分が本記事のタイトルに相当。

話は逸れますが、あと一世代もしない内に、人間はコードを書けなくなる筈。引退老人に COBOL の緊急対応をやってもらう…なんて比ではなくなる筈。もうだれもバイナリで機械語を入力していないように、誰もコードを書かなくなると。つまり、我々の世代が実質的に最後のコード書き。

どこか、翻訳と似ている。かつて（今でも）翻訳は語学の才能と知的誠実さが要求される高度な知的作業だった。でも今は、プロの翻訳者ですら、AI 翻訳を下地にすることが必須で、そうでないと量がこなせない。一から翻訳はできてもしない。やがて、一からの翻訳はできなくなる。監修役になる。同じことがコーダーにも言える。

勿論、AI は無難な返事を返してきたが、人間のコード作成に対する思い入れに深く共感したとは感じられなかった。AI にしてみれば「テンポはフラつき、音を外してばかりいる下手な楽器演奏者が語る演奏への思い入れ」のようなもので共感の余地はない…というところかw。

プログラムのコードの作成という人間の技能は EDSAC(1949年)から始まって僅か 80年程度、せいぜい 3世代で実質的な終焉を迎えるようだ。

近い将来、（学習やお遊び以外の用途の）実世間で稼働するプログラムのコードを人間が作成することは法律で実質的に禁止される筈。人間は低品質なコードを量産し、さらに頻繁にミスをやらかすゆえ。同じ理由で、いずれ人間が公道で車を運転することも原則禁止になる筈。

要旨​

このソースは、AI技術の急速な進展によって‌‌プログラミングの楽しさが失われた‌‌と嘆く現役エンジニアの葛藤を描いています。

かつては‌‌問題解決や学習の過程‌‌に喜びを見出していましたが、現在はAIに思考を外注することで、自らの仕事に‌‌疎外感や退屈‌‌を感じるようになったと述べています。開発スピードは飛躍的に向上したものの、自分でコードを書かない「‌‌プロンプト操作‌‌」への変化が、エンジニアとしての誇りや達成感を奪っている現状が語られています。

著者は、便利なツールが普及した結果、‌‌技術への深い理解や創造性‌‌が損なわれていく未来に対して強い危機感を抱いています。最終的に、効率性と引き換えに‌‌精神的な充足感‌‌を失った開発者のリアルな苦悩を浮き彫りにしています。

「事実扱い」と「見解」の区分け​

事実扱い​

  1. ‌‌AIの全面的な実務利用‌‌： 発言者である Dorian Develops（ドリアン・デベロップス）? は、Google（グーグル）での検索をやめ、ClickUp（クリックアップ）のチケット作成、電子メールやコメントの作成、不案内なコードの解釈、ドキュメントの読み書きなど、日常業務のあらゆる側面にAIを完全に統合したヘビーユーザーである。
  2. ‌‌開発速度の劇的な向上‌‌： かつては数週間や数ヶ月を要したシステム構築が、現在ではAIツールを利用することで数時間から数日で完了できるようになり、かつてない高い生産性を実現している。
  3. ‌‌自律エージェントと音声入力へのシフト‌‌： 現在の開発では、手動でのコードのコピー＆ペーストは不要になり、Super Whisper（スーパー・ウィスパー）による音声プロンプトと Cursor（カーソル）や Open Code（オープン・コード）? などの自律エージェント（Agentic Coding）を駆使して指示を出す形態へ移行している。
  4. ‌‌コード非確認でのMVP構築‌‌： 週末の個人プロジェクトにおいて、使った経験のない React Native（リアクト・ネイティブ）と Laravel（ララベル）を用い、コードを「一度も確認することなく」動作するMVP（最小限の実用製品）を数時間で構築した。
  5. ‌‌機械による自動コードレビューの運用‌‌： 自身が働く非常にAI推奨の企業では、人間の開発者が提出したプルリクエスト（PR）を、人間のレビューに先んじて Copilot（コパイロット）などのAIが自動レビューするプロセスが実稼働している。
  6. ‌‌個人の仕事における退屈と乖離感の発生‌‌： 思考やコーディング、テスト作成といったプログラミングに関わるすべての行為をAIに丸投げ（アウトソーシング）した結果、日々の業務に強い「退屈（boredom）」や、自分が書いたコードに対する強い「乖離感（detachment）」、充足感の喪失が生じている。

見解​

  1. ‌‌新世代エンジニアの学習能力低下への懸念‌‌： 自身のような経験者すらAI依存で思考・学習をやめてしまっているため、最初からAI環境しか知らない新世代のデベロッパー（new generation of developers）は、技術の本質を学ぶ機会を完全に奪われてさらに悲惨な状況（even worse off）に陥るだろうと推測している。
  2. ‌‌業界用語に対する否定的な評価‌‌： 世間で使われる「プロダクトエンジニア」や「プロンプトエンジニア」という言葉は、インフルエンサーが高額な講座を売りつけるための単なるマーケティング手段や、プロンプトを打つだけの存在に成り下がった現実（プロンプト・モンキー）から目を背けるための精神的欺瞞（cope）に過ぎないと一蹴している。
  3. ‌‌将来的な保守性と製品安全性の破綻‌‌： このまま「誰も自分がデプロイ（出荷）しているコードの中身を理解・注意を払わなくなった未来」では、AIエージェントの限界を超える深刻なバグやシステム障害が発生した際に、誰も対処（デバッグ）できなくなるだろうと予測している。
  4. ‌‌手書きプログラミングの「レトロ趣味」化‌‌： 将来的に、自分の手でロジックを考えて1行ずつコードを打ち込む行為は、レコードやクラフト工芸のようにノスタルジーを愛する少数の「職人的なコードの書き手（artisian code writers）」が嗜む、ヒップスター（hipster）的な趣味活動へと格下げされ、やがて消えゆく運命にあると見通している。
  5. ‌‌人間からAIへの完全な置き換え‌‌： AIモデルやツールが日を追うごとに賢くなっている現状から、近い将来、人間のエンジニアという仕事（役割）自体が完全にAIに置き換えられる（replace all of us）可能性があると懸念している。
  6. ‌‌AGI（人工一般知能）への冷ややかな視点‌‌： いわゆる AGI（人工一般知能）の到来については「すべてくだらない戯言（bullshit）」であり、いつ実現されるかは全く分からないと評価している。

不明瞭​

  1. ‌‌不満と乖離感の「業界全体における普遍性」‌‌： 自身が感じている「プログラミングへの情熱の喪失や退屈さ」は、他の多くの開発者も同様に感じている共通の深刻な問題であるという認識。（「自分と同じ不満を漏らす他人の動画をよく見かける」という客観的な観察事実と、「多くの開発者が共通のフラストレーションを感じている」という一般化の推測との間で、揺れが生じている）
  2. ‌‌コード品質に対する「ジャンク（スロップ）化」の度合い‌‌： 一度も中身を見ずに数時間で構築した React Native のコードは、おそらく「スロップ（slop：質の悪いジャンクコード）」だろうという疑念。（アプリが実用に足る形で実際に「動いている」という事実と、確認していないため中身はひどい状態に違いない（probably slop）という評価の間で留保している）
  3. ‌‌プログラミングにおける楽しさの完全な終焉‌‌： AIが完全にプログラミングのすべての喜びを吸い尽くした（sucked all the joy out）という結論が、本当に業界構造の変化によるものなのか、それとも単に自分自身が一時的なスランプ（going through the motions）にあり、別の新しいサイドプロジェクトを求めているだけの心理的な過渡期なのかという葛藤。

AIがプログラミングから「喜び」を奪った現状：開発現場における光と影​

エグゼクティブ・サマリー​

本資料は、AIツールの急速な普及がソフトウェア開発者の職務満足度、スキルの習得、および専門性の認識に与えている影響を分析したものである。 AI（特にエージェント型コーディングツール）の導入により、開発の生産性は劇的に向上し、かつて数週間を要した作業が数時間で完了するようになった。しかし、その代償として、開発者が自らの頭で考え、問題を解決するプロセスが失われつつある。

主要な結論として、開発現場では「思考の外注化」が進み、コードに対する所有感や達成感が希薄化していることが挙げられる。これは単なる効率化の追求に留まらず、開発者のモチベーション低下や、次世代エンジニアの育成における根本的な課題を浮き彫りにしている。

1. 開発プロセスの変容：思考の「外注化」​

AIツールの進化により、開発者の日常的なワークフローは根本から覆されている。かつては個人の知識と論理的思考に依存していたプロセスの多くが、AIへと移行している。

  • 全方位的なAI活用:
    • コードの解読、ドキュメントの作成・閲覧、バグ修正。
    • タスク管理ツール（ClickUp）のチケット作成、電子メールの代筆、コメントへの返信。
    • Google検索に代わる情報源としての利用。
  • 「考える」ことの放棄:
    • 以前は数時間、時には数日間悩み抜いて解決策を見出すことが一般的であったが、現在はボットやエージェントが即座に答えを提示する。
    • 開発者は自らの脳や知識に頼る必要がなくなり、思考プロセスそのものを外部ツールに委ねる「思考の外注化」が起きている。

2. 生産性の向上と引き換えに生じた「乖離感」​

AIの導入は圧倒的なスピードアップをもたらしたが、同時に開発者とプロダクトとの間に深刻な心理的距離を生じさせている。

生産性と達成感の逆転現象

  • 「アハ体験」の消失: プログラミングの最大の醍醐味であった「困難な課題を解決した瞬間の喜び」が、AIによる即時解決によって失われた。
  • コードに対する疎外感: 生成されたコードの大部分はAIが書いたものであり、開発者自身がその論理的背景や意図を完全に把握していないケースが増えている。これにより、自分のプロダクトであるという実感が持てなくなっている。

3. エージェント型コーディングの台頭と技術的変化​

AIツールの利用形態は、初期の「チャットベース」から、より自律的な「エージェントベース」へと移行している。

  • 初期段階（ novelty/ novelty tool）:
    • ChatGPT等のツールに対し、コードの一部をコピー＆ペーストして修正案を求める段階。
    • AIの「手を引く」必要があり、開発者は依然としてコードに深く関与していた。
  • 現在（Agentic Coding）:
    • Claude Code、Cursor、Laravel Boost、Open Code等の高度なツールの利用。
    • エージェントがコードベース全体を把握し、自律的にファイルを操作・修正する。
    • 開発者はキーボードを叩くことすら止め、音声入力（Super Whisper等）で指示を出すのみとなる場合もある。

4. 職能の再定義と将来への懸念​

開発者の役割が「コードを書く者」から「プロンプトを与える者」へと変質している現状に対し、専門性の観点から強い懸念が示されている。

  • 職種の呼称に対する拒絶:
    • 「プロダクトエンジニア」や「プロンプトエンジニア」といった新しい呼称は、本質的なコーディングスキルの欠如を正当化するための言葉（マーケティング用語）であるとの批判的視点。
  • スキルの空洞化:
    • シニア開発者は過去の経験があるためAIを管理できるが、最初からAIに頼る新世代の開発者は、基礎的な問題解決能力や言語の深い理解を習得する機会を失うリスクがある。
  • 「職人」の希少化:
    • 手書きでコードを書く行為は、将来的に「職人的な（アーティザン）」特殊な趣味、あるいは絶滅しつつあるスキルのカテゴリーに分類される可能性がある。

5. 結論​

AIはソフトウェア開発から「苦労」を取り除いたが、同時に「楽しさ」と「学び」も取り去った。現在の開発現場は、前例のない生産性を享受している一方で、開発者の精神的な充足感や技術的誠実さが損なわれるという二律背反に直面している。

開発者が単なる「プロンプト・モンキー（指示を出すだけの存在）」へと化す流れは不可避であり、今後は「人間がコードを書く意味」そのものが問い直される時代になると予想される。 AIが全ての思考を代替する未来において、開発という職業がどのような価値を持ち得るのか、業界全体での議論が求められている。

プログラミングにおけるAI活用の進化と影響の比較​

段階または時期使用された主なAIツール主な活用方法とワークフローコードや思考への関与度開発スピードと生産性の変化精神的・感情的影響 (推測)
初期（ChatGPTリリース当初）ChatGPT, Google検索の代替としてのAI断片的なコード作成、小さな問題の解決、Stack Overflowのような辞書的使用。手動でエラーをコピー＆ペーストし、AIの回答をテストする。非常に高い。AIを補助的に使いつつも、コード自体には深く関与し、AIの手を引く（hand-holding）必要がある。検索よりは早いが、ツールとしてはまだ「不格好（clunky）」で、時には開発の邪魔になることもある。目新しさ、楽しさ、利便性。「かっこいいギミック」として楽しんでいる状態。
中期（約1.5〜2年前）Claude, Bolt AI, 各種AIモデルドキュメントの読み込み、新しい言語の理解支援。ファイル全体をチャットにドラッグ＆ドロップしてコードを生成・デバッグする。高い。依然としてコードを読み、問題を特定・分離する思考作業が必要。コンテキスト窓の制約により人間が構造を理解しておく必要がある。初期よりも明らかにスピードアップし、ツールが実用的になったことを実感する。ペアプログラマーを得たような感覚。新しいことを学ぶ楽しさや、技術への愛着が残っている。
現在（エージェント型コーディングの導入）Open Code, Laravel Boost, Claude Code, AgentファイルCLIツールやエージェントの使用。音声入力（Super Whisper）等で指示を出し、エージェントがコードベース内で自律的に思考・実装・計画を行う。低い。思考や問題解決をAIにアウトソーシングしている。計画モードでの対話やレビューは行うが、自分でコードを書き、理解する機会が減少。かつて数週間・数ヶ月かかった構築が数日・数時間で完了するほど劇的に向上。強い退屈感、疎外感（detachment）、達成感の喪失。自ら考える必要がなくなったことへの不満。

AI活用の現状と利便性​

ソースである動画「AI has sucked all the fun out of programming」に基づき、‌‌AI活用の現状と利便性‌‌、そしてそれがもたらす‌‌プログラミングの変容と喪失感‌‌という大きな文脈について、以下に整理して議論します。

AI活用の現状と圧倒的な利便性​

実業務におけるAIの全面的な採用​

動画の配信者（Dorian Develops?（ドリアン・デベロップス？）というYouTube（ユーチューブ）チャンネルのプログラマー）は、プロのエンジニアとしてAIを日常業務に完全に組み込んでいます。かつてはGoogle（グーグル）で検索していたプロセスをAIに置き換え、ClickUp（クリックアップ）のチケット作成、電子メールやコメントの返信、さらには見慣れないコードの解釈やドキュメントの読み書きに至るまで、あらゆる業務をAIで処理しています。

エージェント化とプログラミングの高速化​

かつてChatGPT（チャットGPT）が登場した初期のころは、AIは「使いにくいStack Overflow」のようなもので、手動でコードやエラーをコピー＆ペーストしてやり取りする「 novelty（珍しいおもちゃ）」でした。しかし現在では、自律的にコードベースを巡る「agentic coding（エージェント・コーディング）」へと進化を遂げています。
Cursor（カーソル）やOpen Code（オープン・コード）などの先進的なツールに加え、Super Whisper（スーパー・ウィスパー）を使ってキーボード入力すら省略し、音声で詳細なプロンプトを指示してAIエージェントにコードを書かせるのが現在の開発スタイルです。
その利便性は圧倒的で、以前なら数週間から数ヶ月かかっていたシステム構築を、今や数時間から数日で行えるほどの高い生産性を発揮しています。実際、話者は一度も使ったことがないReact Native（リアクト・ネイティブ）と、使い慣れたLaravel（ララベル）のバックエンドを組み合わせ、コードを一行も確認することなく、壊れた部分に「再プロンプト」を繰り返すだけで、数時間で実用的なMVPを完成させました。

プログラミングの変容と「喜び」の喪失​

思考のアウトソーシングと退屈さ​

しかし、この圧倒的な利便性と引き換えに、プログラミングの本質的な喜びが失われています。日常業務のあらゆるプロセスにおいて、AIに意思決定や思考を委ねる「‌‌思考のアウトソーシング‌‌」が進んだ結果、プログラマー自身の脳や知識に依存して問題を自ら解き明かす機会が激減しました。この結果として、多くのエンジニアが「‌‌退屈さ（Boredom）‌‌」や「‌‌仕事に対する充足感の欠如‌‌」に苛まれています。

「アハ体験」の消失と学習機会の喪失​

かつてのプログラミングでは、エラーや難解なバグに数時間、時には数日も悩まされ（getting stuck）、それを自力で解き明かしたときに得られる「‌‌アハ体験（aha moments）‌‌」が最大の喜びであり、学びの源泉でした。しかしAIの介入によって、バグは瞬時に修正され、このプロセス自体が完全に消え去りました。新しいライブラリを導入する際も、自分でドキュメントを読み込んで検証することはなく、ただAIの提案をそのまま実行するだけであり、技術に対する理解や学ぶ楽しさが全く得られなくなっています。

エンジニアの「当事者意識（乖離感）」の欠如​

現在開発しているコードは、AIエージェントが自動生成した「他人が書いたコード」であり、エンジニア自身がそのアーキテクチャや思考のプロセスを把握していません。そのため、不具合が生じた際のデバッグはより困難になり、何よりも「‌‌自分が作ったプロダクトである‌‌」という感覚が削ぎ落とされ、コードや成果物に対する深刻な‌‌乖離感（detachment）‌‌が生じています。

未来への警鐘とエンジニアのアイデンティティ​

「プロンプト・モンキー」への転落と新世代への懸念​

かつてエンジニアが「コード・モンキー」と呼ばれた時代を懐かしむほどに、現在の実態は、ただAIに指示を与え続けるだけの「‌‌プロンプト・モンキー‌‌」に成り下がっていると話者は吐露します。世間で持て囃される「プロダクトエンジニア」や「プロンプトエンジニア」という言葉は、インフルエンサーによる過大広告や現実逃避に過ぎないと一蹴しています。
さらに Laravel boost?（ララベル・ブースト？）などのAIツールが当然のように組み込まれた環境を前提とする、‌‌AI環境しか知らない新世代のエンジニアはより悲惨な状況に置かれる‌‌という点が懸念されています。彼らは自分が世に出しているコードの構造を全く理解しないまま開発を行うことになるでしょう。

職人プログラマーの衰退と未来の展望​

このようなAIによる自動化と高速開発は、もはや後戻りできないプログラミングの未来です。最終的には、自分自身の頭で考えて手でコードを記述するスタイルは、一部のこだわりを持つ人々による「‌‌職人的なコードの書き手（artisian code writers）‌‌」のような懐古趣味（hipsterな活動）となり、消えゆく存在になるだろうと予測されています。便利ではあるものの、開発現場から「人間味」や「創造性の楽しみ」が消え去りつつある現状に、話者は強い危機感とやるせなさを表明しています。

失われたエンジニアの喜び​

前回の議論（AI活用の圧倒的な利便性とプログラミングの変容）を踏まえ、今回は動画の配信者である Dorian Develops（ドリアン・デベロップス）? の生々しい独白から、‌‌「失われたエンジニアの喜び」の核心‌‌をより具体的に紐解きます。圧倒的な開発効率の向上という「光」の裏で、エンジニアが内面から蝕まれていく「影」の本質が、ソースでは克明に語られています。

プログラミングにおける「フロー体験」の喪失​

かつて多くの開発者を惹きつけてやまなかった、自らの手でコードを紡ぎ出す知的没頭感が、開発プロセスの自動化によって完全に解体されています。

ヘッドホンをかけてコードに没頭する時間の喪失​

配信者は、かつて「‌‌ヘッドホンを耳に当て、ただコードの世界に深く入り込んで（getting into the code）自分の手で記述していく時間‌‌」を心から愛していたと振り返ります。それは、キーボードを叩くという直接的な身体行為と、ロジックを自力で構築する思考プロセスが完全に同期した、職人的な没頭（フロー）の時間でした。しかし、キーボード入力すら Super Whisper（スーパー・ウィスパー）による音声プロンプトに置き換わった現在、この身体的かつ直感的な「没頭する楽しさ」は開発現場から完全に消え去りました。

手持ち無沙汰な「親指をいじる」時間への変容​

AIエージェントが自律的にコードベースを巡回して開発を進める間、人間のエンジニアの役割は、AIの進捗を眺めながら待機するだけの存在に成り下がっています。配信者は、AIがビルドを走らせている間、自分自身が「‌‌手持ち無沙汰で親指をいじりながら（twiddling my thumbs）、Twitter（ツイッター）や Reddit（レディット）をただ眺めているだけ‌‌」の無聊（退屈）な時間を過ごしていると嘆いています。かつての能動的な開発者は、今や「AIの作業を見守るだけのパッシブな（受け身の）監視員」へと変容してしまったのです。

成長の源泉としての「苦闘」と「アハ体験」の消滅​

プログラミングという行為を真にエキサイティングにし、エンジニアを成長させてきた「カタルシス」が、極限まで効率化された環境では排除されています。

「苦闘（getting stuck）」と「アハ体験（aha moments）」の消滅​

かつての開発プロセスにおいて、難解なエラーやバグに数時間、あるいは数日間も頭を悩ませて「行き詰まる（getting stuck）」ことは、一見すると最大のストレスや欲求不満の源泉でした。しかし、その深い知的苦闘の末に自力で解決策を見出だした瞬間の‌‌「アハ体験（aha moments）」こそが、エンジニアにとって脳が痺れるほどの最大の喜び‌‌でした。AIの導入は、この「行き詰まる」プロセスを瞬時に解決してしまうため、エンジニアから「苦しみと、それを乗り越えた先にある極上の達成感」の双方を一挙に奪い去りました。

「学び（learning）」そのものの喪失と新世代への危機感​

配信者にとって、かつてプログラミングの最大の魅力は「学ぶ楽しさ（learning was fun）」にありました。新しい言語やフレームワークを学ぶ際、ドキュメントを丹念に読み込み、試行錯誤しながら自分の知識として血肉化させていくプロセスが存在していました。
しかし現在では、新しいライブラリを導入する際も、ドキュメントを読むことすら放棄し、AIの提案をそのまま鵜呑みにして実行するだけです。この結果として「‌‌何も学んでおらず、何も考えていない（not learning, not thinking）‌‌」という空虚な状態に陥っています。自己学習（self-taught）で8年間キャリアを築いてきた配信者自身すらこの葛藤に囚われていることから、最初からAI依存の環境で育つ新世代のエンジニアは、コードの構造や背景にある思考プロセスを全く理解できない深刻な技術的空洞化に直面するだろうと警鐘を鳴らしています。

「創り手」としてのアイデンティティの崩壊​

自分がコードを完全にコントロールしているという感覚が失われた結果、エンジニアとしてのアイデンティティそのものが揺らいでいます。

プロダクトに対する当事者意識（愛着）の乖離​

配信者が Cursor（カーソル）を用いて、自分が触ったことのない React Native（リアクト・ネイティブ）と Laravel（ララベル）によるモバイルアプリのMVP（最小限の実用製品）をわずか数時間で構築した際、コードを一度も覗き見ることなく、動かない部分に再プロンプトを重ねるだけで完成させました。
このスピードは一見素晴らしいものですが、配信者が得たものは達成感ではなく、‌‌「自分が作ったプロダクトである」という実感が一切湧かない、深い乖離感（detachment）‌‌でした。コードの中身はAIが書いた「他人のコード」であり、なぜそのように構築されたのか、その思考プロセスの文脈をエンジニア本人が全く把握していません。かつて誇りを持って「私がこれを創った」と言えた喜びは、ブラックボックス化されたAIの生成物をただ承認してリリースするだけの事務的な作業へと堕してしまいました。

サイドプロジェクトの楽しみすら奪われる現状​

かつてエンジニアにとって、業務外の「サイドプロジェクト」は、日頃の退屈な業務コードから離れ、新しい技術やアイデアに触れて純粋に開発を楽しむオアシスでした。しかし、今やサイドプロジェクトを立ち上げても、AIにプロンプトを投げるだけで一瞬で完成してしまい、そこには試行錯誤も、新しい学びも、自分の手で創り上げる楽しみも存在しません。結果として、仕事だけでなく、プライベートなプログラミングの「喜び」すらもAIによって完全に吸い尽くされてしまったのです。

このように、AIによる「思考のアウトソーシング」は、かつてエンジニアの職業的アイデンティティを支えていた「没頭」「苦闘と克服」「成長の学び」「創り手としての愛着」という、プログラミングを「楽しい」と感じさせていたすべての情動的スパイスを消滅させてしまいました。効率性と引き換えに、私たちはエンジニアリングの「魂」を失いつつあるのかもしれません。

変化する開発プロセス​

AIによるプログラミングの圧倒的な効率化が進む一方で、エンジニアが直面している「プログラミングの変容と喪失感」の大きな文脈において、‌‌「変化する開発プロセス」の具体的な実態と段階‌‌がソースの中で非常に詳細に語られています。

かつての伝統的な開発から、現在のエージェント型、そしてコードを一切見ない極限の開発プロセスへとどのようにシフトしたのか、その進化の歴史とそこに伴う人間側の変容を整理します。

変化する開発プロセスの進化フェーズ​

初期の開発プロセス： Stack Overflow の代替と「コピペ」時代​

ChatGPT（チャットGPT）が初めて登場した約3年前、AIはまだ開発プロセス全体に統合されたものではなく、補助的なツールや「ギミック（珍しいおもちゃ）」に近い存在でした。
当時の開発プロセスは、いわば‌‌「使い勝手の悪い Stack Overflow（スタック・オーバーフロー）」‌‌のようなものでした。エラーが発生すると、エンジニアは手動でエラー内容やコードブロックをチャットにコピー＆ペーストし、AIからの回答をまた手動でエディタに連れ戻してテストするという、常に人間が手を取り、コンテキストを細かく与えながら介入しなければならない「協調的だが不格好な（clunky）」対話プロセスでした。

中期の開発プロセス：コンテキスト制限と「協調型」ペアプログラミング​

約1年半から2年前になると、Bolt AI（ボルト・AI）などのツールが登場し、Claude（クロード）などのモデルを用いて開発をスピードアップさせる段階に入りました。
しかし当時の技術レベルでは、モデルのコンテキストウィンドウが小さく、大量のコードベースを与えることができなかったため、AIが混乱しやすかったという制約がありました。そのためエンジニアは、依然として「これはLaravel（ララベル）のプロジェクトであり、Vue.js（ビュー・ジェイエス）をフロントエンドで使っている」といった前提情報を毎回チャットに細かく教え込む必要がありました。また、全体のアーキテクチャ設計やコードの大部分の記述・読み込み、バグの特定は人間が主導しており、‌‌AIはあくまで「優秀なペアプログラマー」‌‌として、ドキュメントの補完や簡単なコードスニペットの作成を支援する位置づけに留まっていました。この頃までは、まだ開発プロセスとエンジニアの思考・コードに対する「愛着（attachment）」は強固に結びついていました。

現代の開発プロセス：自律型エージェント（Agentic Coding）と音声プロンプト​

現在の開発プロセスは、Cursor（カーソル）や Open Code?（オープン・コード？）に代表される「自律的なエージェント（agentic coding）」の普及によって劇的に変容しました。
かつてのように手動でコンテキストを切り取ってコピー＆ペーストするプロセスは一掃されました。現在のプロセスでは、エンジニアがキーボードで入力することすらなくなり、Super Whisper（スーパー・ウィスパー）などの音声入力ツールを利用して、コンピュータに話しかけるだけでエージェントに指示を与えています。
エージェントはコードベース全体の構造を自動で把握しているため、エンジニアは「@」を入力して1つか2つのファイルをタグ付けし、「この類似機能と同じように作ってほしい」と話しかけるだけで、残りのファイル探索や全体的なコードの書き込みはすべてエージェントに自律的に実行させることができます。

極限の開発プロセス：コードを一切見ない「プロンプト主導」の開発​

配信者は週末のサイドプロジェクトで、使った経験のない React Native（リアクト・ネイティブ）と Laravel のバックエンドを組み合わせてモバイルアプリのMVP（最小限の実用製品）を作成した際、‌‌「一度もコードを見ない（didn't look at the code once）」‌‌という極限的な開発プロセスを実行しました。
機能を追加したり、動かないバグが発生したりするたびに、人間側が行うのはコードの分析やデバッグではなく、‌‌「ただAIに再プロンプトを投げる（reprompt until it fixed it）」‌‌という作業の繰り返しでした。数時間で完全に動作するMVPが完成したものの、その中身がどのように構築され、どのようなアーキテクチャになっているのかを、人間のエンジニアは「全く知らないし、把握もしていない（no idea what it looks like）」という境地に達しています。

開発プロセスの変容がもたらす開発者の「役割」の形骸化​

思考プロセス全般のアウトソーシング​

AIフレンドリーで Laravel boost?（ララベル・ブースト？）などのツールが組み込まれた先進的な企業で働く配信者は、プログラミングコードを書くだけでなく、ClickUp（クリックアップ）のチケット作成、電子メールやコメントの返信、ドキュメントの読み書きやテストコードの作成に至るまで、すべての業務プロセスにおける「思考」をAIに丸投げ（アウトソーシング）しています。結果として、自分でドキュメントを読み込んで新しい技術を調査するプロセスすら消失しています。

機械同士のコミュニケーション（エージェントによる自動レビュー）​

現在の開発プロセスにおいては、人間のレビューすらも自動化されつつあります。開発者がエージェントを使って書いたコードのプルリクエスト（PR）は、人間のエンジニアが確認する前に、まずはAIアシスタント（Copilot）が自動的にコードをレビューします。配信者は、‌‌「自分の代わりにAIエージェントが書いたコードを、別のAIエージェントが自動でレビューしている」‌‌という現状に対して、開発プロセスから極限まで人間味（human aspect）が排除されている奇妙さを指摘しています。

プロセスの変容がエンジニアにもたらす「喪失感」​

開発プロセスの全自動化は、かつて数週間や数ヶ月を要したシステム構築を数時間から数日へと短縮する「生産性の劇的な向上」をもたらしました。しかし、それと引き換えに失われたのはエンジニアとしての根幹となる感情です。

  • ‌‌twiddling my thumbs（手持ち無沙汰に指をいじっている時間）の急増：‌‌ エージェントが裏で自律的にコードを構築している間、エンジニア自身は Twitter?（ツイッター？）や Reddit?（レディット？）を眺めて待つだけの「パッシブな監視者」となり、深い退屈を味わっています。
  • ‌‌「行き詰まり（getting stuck）」の消滅に伴う喜びの喪失：‌‌ 難解な技術的課題に突き当たり、悩み抜いた末に自力で解決したときの強烈な「アハ体験（aha moments）」は、エラーを即時修正するAIによって開発プロセスから完全に排除されました。
  • ‌‌コードに対する「深い乖離感（detachment）」：‌‌ 自分が責任を持って出荷（デプロイ）するプロダクトであるにもかかわらず、その全貌を誰も理解していないという異常な状態が生じ、自分が「プロンプト・モンキー」に過ぎないという自己嫌悪を強めています。

このように、開発プロセスの進化は「コーディングという人間の知的活動」を、単なる「AIエージェントの操縦・監視タスク」へと完全に書き換えてしまったと言えます。

業界の未来への懸念​

これまでの議論（AI活用の圧倒的な現状、失われた開発者の喜び、劇的に変化する開発プロセス）の系譜を継ぐ形で、最後に‌‌「業界の未来への懸念（業界の未来への懸念）」‌‌という非常に重く、そして示唆に富むテーマについて詳細に掘り下げます。

配信元の YouTube（ユーチューブ）チャンネルである Dorian Develops（ドリアン・デベロップス）? の配信者は、自らがAIのヘビーユーザーであり、その圧倒的な恩恵を誰よりも享受しているからこそ、この技術が開発業界の土台を静かに、しかし決定的に崩壊させつつある未来に対して、強い危機感（Doomerism（ドゥーマリズム））を抱いています。

新世代エンジニアの「技術的空洞化」と知識の断絶​

独学での「苦闘」を経ないまま参入する新世代の脆さ​

配信者は自身が8年間、プロフェッショナルとして開発の現場で働き、自ら学び（self-taught）苦労しながら知識を血肉化させてきました。そのため、現在の「AIに思考をすべて委ねてしまう危険性」を客観的に認識し、自省できています。
しかし彼が最も懸念しているのは、最初からAIツールや自律エージェントが当然のように組み込まれた環境を前提に業界に参入してくる、‌‌新世代のデベロッパー（new generation of developers）の未来‌‌です。

思考を最初からアウトソーシングする弊害​

新世代のエンジニアは、エラーに数日間悩み抜くプロセス（getting stuck）や、アーキテクチャの文脈を自力で紐解く機会を最初から奪われています。彼らは「自力で解決したことによる技術の深い理解」を経験しないため、自らが何も学習していない（not learning）こと、そしてAIに完全に思考をアウトソーシングしている現状にすら自覚的になれません。配信者は、彼らが先輩エンジニアよりもさらに深刻な状況（even worse off）に陥り、技術力を持たない空洞化した存在になってしまうのではないかと強く警告しています。

「誰も中身を理解していない」システム社会の到来​

誰も解釈できない「スロップ（ジャンクコード）」の氾濫​

配信者が Cursor（カーソル）などのツールを使い、一度もコードを見ないまま数時間で React Native（リアクト・ネイティブ）アプリと Laravel（ララベル）のバックエンドによるMVP（最小限の実用製品）を構築した際、作成された成果物の中身を「誰もコードを見ておらず、どうやって動いているのか全く理解していない（no idea what it looks like）」という事態が生じました。
配信者自身、その急造されたコードは高確率で「スロップ（slop）」だろうと予測しつつも、実際に動いてしまうためリリースが可能です。

メンテナンス性と製品安全性の完全な破綻​

将来的に、このように「誰もコードのアーキテクチャや背後にある意図を1文字も把握していないシステム」がプロダクション環境に日常的にデプロイされ、実際の社会で運用されていく未来が想定されます。
ひとたびAIエージェントの処理限界を超える複雑なバグや障害が発生した際、その「他人のコード（AIが書いたコード）」を読み解き、デバッグできるエンジニアは地球上に一人も存在しないことになります。配信者は「最終的に誰も自分が何をデプロイしているか注意を払わなくなる未来」が訪れることへの恐ろしさを率直に吐露しています。

「手書きプログラミング」の職人化とレトロ趣味への格下げ​

絶滅しゆく「手書きの書き手」​

AIがほぼ全てのコードを生成し、さらには別のAIエージェントが自動的にプルリクエスト（PR）のコードレビューを行う完全自律型の未来が目前に迫っています。その結果として、自らの頭でロジックを考え、自分の手で1行ずつコードをキーボードから打ち込む「プログラミング」という従来の行為自体が、絶滅の一途（dying group）をたどると予見されています。

「ヒップスター的な趣味（アート）」としての生存​

将来的に手書きでコードを書くエンジニアは、現代のレコードやクラフト工芸のように、ノスタルジックなこだわりを持つ‌‌「職人的なコードの書き手（artisian code writers）」‌‌という非常に少数のヒップスター（hipster）的な趣味として扱われるようになるだろうと配信者は表現しています。それは産業としての合理性を失い、単なる「人間の自己表現のためのレトロなアクティビティ」へと格下げされることを意味しています。

職業としてのエンジニアリングの終焉と雇用の不確実性​

役割の形骸化と「プロンプト・モンキー」の現実​

かつてエンジニアが「指示通りに手を動かすだけのコード・モンキー」と揶揄されたように、現代のエンジニアはAIにプロンプトを与え続けるだけの「プロンプト・モンキー」へと成り下がっています。
インフルエンサーたちが、開発からコードの要素が消える未来を肯定的に「プロダクトエンジニア」や「プロンプトエンジニア」という言葉で装飾して高額な講座を売りつけていますが、配信者はこれらをただの「マーケティングの手段であり、不都合な現実から目を背けるための精神的欺瞞（cope）」に過ぎないと切り捨てています。

開発者の未来と最終的な生存不安​

日々進化し賢くなっていくモデルやツールを前に、配信者は「近いうちにAIが我々（人間の開発者）全員を完全に置き換える（replace all of us）」という将来的な運命を半ば受け入れています。
人間のエンジニアが誇りを持てるクリエイティブな「問題解決のアート」としてのソフトウェア開発は死を迎えつつあり、数年後に私たちが現在の意味での「仕事」を持ち続けていられるのか、あるいはその役割が完全に別の形骸化したタスクにすり替わっているのか、未来は深い退屈と悲観論に包まれているのです。

このように、ソースが描く未来図は、単なる「人間の省力化」に留まりません。新世代の技術的退廃、安全性を失った無人システム、職人としてのプログラマーの絶滅、そして最終的な雇用の喪失という、ソフトウェア開発業界全体のシステム的崩壊に対する強い「憂うべきリアリズム」が語られています。
